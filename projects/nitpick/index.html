Parallel AI code review your agent can gate on.

nitpick runs five specialist AI reviewers and three scanners against a GitHub pull request or a ref range at the same time; every AI agent gets its own disposable sandbox. A verifier on a different model family checks every finding before you see it. Humans get a live terminal and a markdown report; agents and CI get JSON and exit codes.

security, performance, architecture, testing and dx — in any combination, in parallel.

🛰️

How it works

Every agent gets its own throwaway sandbox.

Each AI agent runs in an Upstash Box. Repository code never runs on your machine.

  1. Fetch

    PR or compare metadata comes from the GitHub API, including whether the repository is private.

  2. Fan out

    Each reviewer role, the linter and the summarizer get their own Box: clone, check out the head, write the diff, delete stored git credentials — then the agent runs.

  3. Find

    Agents return schema-validated findings (severity, confidence, file, line, evidence, recommendation) while the secrets and dependency scanners run in parallel.

  4. Verify

    A verifier on a different model family re-reads the code and confirms, adjusts, deduplicates or rejects each finding.

  5. Decide

    You triage (or --auto). The verdict comes from accepted findings: a severity × confidence risk score, blockers (critical/high with ≥ 0.7 confidence) and a recommendation.

  6. Clean up

    Every Box is deleted when its job finishes, and again on exit, Ctrl+C or SIGTERM.

Built for agents & CI

One atomic step: point at refs, read JSON, branch on the exit code.

The building blocks: ref mode (no PR needed), --auto, --non-interactive, --json, --exit-on and --no-report (keeps the working tree clean).

Exit codeMeaning
0Success, or --exit-on none
1Fatal error — or --exit-on is set and every AI reviewer failed, so the gate fails closed
2The --exit-on condition matched
130Interrupted (Ctrl+C)

Fix-until-clean

Convergence loop

Push, run with --exit-on blockers. On 2, read verdict.blockers, edit each filePath:lineStart per its recommendation, commit, repeat. On 1, stop and surface stderr.

Pre-PR polish

One-pass cleanup

Run once in ref mode, apply critical/high acceptedFindings, group the fixes with verdict.suggestedCommits, then open the PR.

CI gate

Reviewer bot

On every push: --auto --non-interactive --post-review --exit-on changes-requested. The review lands on the PR; the job fails on 2.

What nitpick deliberately does not do
  • No git push, commits, branch creation or history rewrites — the agent applies fixes itself.
  • No state kept between runs.
  • No network calls other than GitHub, Upstash Box and OSV.dev.

Security model

Designed for untrusted pull requests.

A PR can contain prompt injections or malicious build scripts. The design assumes that can happen.

Runs onWhat runs thereWhat it can access
Your machineThe CLI, the secrets scanner, verdict and reportingYour tokens; never runs repository code
Upstash BoxAgents and repository code (e.g. the linter)The cloned repository; no GitHub credentials once setup finishes
GitHubMetadata and diff reads; review posting with --post-reviewThe read token; the review token only when posting
OSV.devVulnerability lookupsNames and versions of newly added dependencies

Honest disclosure: nitpick was vibe coded — written mostly by AI coding assistants under human direction and review. It has a test suite, CI, pinned dependencies and a documented security model, but it is young software. Read the security model before pointing it at private code, and give it least-privilege, fine-grained tokens.

Install

Up and running in a minute.

Needs Node.js ≥ 22, pnpm 10 and an Upstash Box API key with agent access. Credentials come from environment variables — nitpick does not read .env files itself. Public repositories need no GitHub token.

Quick start
# clone, install, run interactively
git clone https://github.com/ilterkavlak/nitpick.git && cd nitpick
pnpm install
export UPSTASH_BOX_API_KEY=...
pnpm start
Global nitpick command
# the tarball path must be absolute for pnpm add -g
pnpm pack
pnpm add -g "$PWD"/nitpick-*.tgz
nitpick --help
Usage
# browse repos and pick a PR
nitpick

# review a PR with human triage
nitpick review https://github.com/org/repo/pull/42

# review a branch without a PR
nitpick review --repo org/repo --base main --head feature

# coding-agent fix loop: JSON to a file, exit code as the signal
nitpick review --repo org/repo --base main --head feature \
  --auto --non-interactive --no-report --json nitpick.json --exit-on blockers
